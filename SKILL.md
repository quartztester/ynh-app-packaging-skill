## Environment conventions (defaults = this repo's maintainer; override for your setup)
- `GH_ACCOUNT` — GitHub account that owns the `<app>_ynh` package repos (default `quartztester`)
- `GH_TOKEN_FILE` — classic PAT file, mode 600, git credential.helper wired to it; export as `GH_TOKEN` for the `gh` CLI (default `/root/.gh_token`)
- `WORKSPACE` — root dir where `<app>_ynh` packages are bootstrapped (default `/root/workspace`)
- `COMMIT_AUTHOR` — noreply commit identity, `<id>+<login>@users.noreply.github.com` shape (default `91350035+quartztester@users.noreply.github.com`)

## When to Use
- Writing or debugging a YunoHost app package (manifest.toml, scripts/, conf/); diagnosing install/upgrade/backup/restore/config-panel failures on YunoHost 11+/12.
- "Install <app> from GitHub" → check for an EXISTING `$GH_ACCOUNT/<app>_ynh` repo FIRST (`api.github.com/users/$GH_ACCOUNT/repos` filtered on `_ynh`); never stand up an upstream Docker route while that `_ynh` exists.
- "Would X be easy to package?" → feasibility probe (references/quality-gates.md): answer from cheap evidence, install nothing.
- Subdomain-vs-subpath decisions; binding app config to env files.
- "Make the app log YunoHost users in like forgejo/nextcloud" → research the app's auth backends FIRST (LDAP/OIDC/SAML/trusted-header/local), then wire per references/auth-backend-integration.md — before writing any script.
- "Audit my packages / does anything need updating?" → fleet audit of all `$GH_ACCOUNT` _ynh repos vs upstream + the box, read-only (references/upstream-repo-staleness-triage.md).
- "Test/benchmark/measure this skill itself" (package an app with a fresh agent to score the skill) → references/benchmarking.md: with-skill vs baseline runs, calibrated static rubric (scripts/grade_static.py), parent-run live gates; judged on ecosystem usability, never line-parity with the official package. ## Golden rules
0. ENVIRONMENT GUARD, before any packaging work: the box must be YunoHost 12.x with helpers 2.1 — `yunohost --version` major 12 AND `ls /usr/share/yunohost/helpers.v2.1.d/ >/dev/null`. On mismatch (YNH 13+, helpers ≠ 2.1): STOP — every trap below is validated against that core only; re-audit references/official-docs.md and re-run one covered app's gates before writing scripts here.
1. NATIVE PACKAGING ONLY — no Docker, ever (user policy).
2. BOOTSTRAP FROM example_ynh, always: `mkdir -p $WORKSPACE/<app>_ynh && tar xzf <skill_dir>/templates/example_ynh-snapshot.tar.gz -C $WORKSPACE/<app>_ynh`, then edit in place — never hand-write manifest/scripts or copy an old package's layout. Refresh the snapshot from upstream if older than a few weeks; re-fetch https://doc.yunohost.org/en/dev/packaging instead of recalling (all pages indexed + doc-only facts: references/official-docs.md); diff half-done packages against the snapshot and adopt missing template files.
3. PIN `helpers_version = "2.1"` in [integration] — without it a packaging_format=2 app silently loads dead 2.0 helpers. `scripts/verify_conformance.py` fails on any `ynh_*` call not defined in the local helpers.v2.1.d (hallucinated helpers are a static lint failure now; renames: references/traps-helpers-and-panels.md).
4. SSO BY DEFAULT for any app with its own login — and pick the auth integration path (LDAP/OIDC/SAML/trusted-header/local) by RESEARCHING the app first, per references/auth-backend-integration.md. NEVER `auth_header=true` on a permission covering Bearer-token API routes (infinite login loop) — `auth_header` DEFAULTS to true in [resources.permissions], so Bearer-covered routes need it explicitly false. Patterns and traps: references/ssowat-integration.md.
5. NO LIVE-ONLY FIXES — `ynh_setup_source` re-extracts on every pass (only `--keep` files survive) and `ynh_config_add` always overwrites managed config, so a box-side fix is UNPROVISIONED until it's in the repo AND landed via `yunohost app upgrade <app> -u <clone>`. Doctrine: references/traps-lifecycle.md.
6. SECRETS live in app settings as the single source of truth; scripts re-render env/config from settings. NEVER regenerate a secret in upgrade/restore — create-once pattern: `ynh_app_setting_set_default --key=x --value=$(ynh_string_random)` (no-op + exports the var when already set).
7. REVIEWER BAR: example_ynh IS the architecture — same file set, same v2 idioms, lean scripts (shared logic in _common.sh, no speculative settings, no comment walls). Deviating AI-generated packages get REJECTED at catalog review. Catalog quality levels (0–8) are bot-assigned from CI; level ≤4 gets the app HIDDEN and its upgrades FROZEN for every installed instance — the Definition of done below is what holds level ≥7.
8. PUBLISH as `$GH_ACCOUNT`: PAT `$GH_TOKEN_FILE` (600, credential.helper wired — never embed the PAT in a remote URL); author `$COMMIT_AUTHOR`; repo <upstream-name>_ynh (manifest id: no `__`, no `.` — live 12.1 also accepts `-` but stay [a-z0-9_] catalog-style; the repo-name mismatch is fine); tag v<version>-ynh<N> AND verify it on the remote (`git ls-remote --tags` — a version bump is not a release until its tag exists upstream; `test_upgrade_from` and store history hang off tags); source tarballs/apt keys as GitHub Release assets. Server-driven changes to published repos: verify on the box, commit, WAIT for explicit user approval before pushing. Branch discipline: a catalog-listed repo's `main` is AUTO-PUBLISHED (catalog tracks HEAD of main, ~4 h rebuild) — work in feature branches, merge to main only fully-gated changes (repo-hygiene.md §Catalog-submission-mechanics).
9. NOTHING LEAKS (ABSOLUTE): no names/emails/domains/usernames/IPs/subdomain inventories in any file, image, or commit history. 3-layer audit (tree grep, full-history grep, image vision-sweep) before EVERY push — procedure: references/repo-hygiene.md.
10. CATALOG-READY EXTRAS ARE A HARD GATE: repo-local `logos/<appid>.png` square RGBA ≥180px with corner alpha verified 0 (catalog repos ship NO logo dir — the file is submitted to YunoHost/apps `logos/` with the catalog PR); REAL doc/screenshots/*.png embedded in README+README_fr; full example_ynh file set (fr docs, PRE_/POST_ docs, dotfiles — canonical, never delete); upstream's real LICENSE text; script modes 755 lifecycle / 644 _common+change_url+config. DESCRIPTION/manifest text follows the catalog-presentation rules (no "self-hosted"/tech/fuzzy-adjective filler, multi-line feature lists, fr pairing): references/repo-hygiene.md. Sourcing ladder: references/repo-hygiene.md.
11. MAIL VIA THE BOX'S POSTFIX whenever the app sends email (signup codes, invitations, notifications): default SMTP to `127.0.0.1:25`, plaintext, no auth — never an external SMTP provider; expose server/port/ssl/from in the config panel with that default. The From address must use a domain the server's outbound relay ACCEPTS (default `app@<install-domain>`; on relayhost boxes only the relay-verified domain works — subdomains of a verified domain are NOT verified). Env flags the app reads as "is this var set" (Ruby `.present?`, Go `os.Getenv != ""`) are TRUE for `"0"`/`"false"` — render them EMPTY for off, never `0`. Prove it with a REAL app-level send + mail.log relay handoff (`status=sent`) — recipe: references/postfix-integration.md §Outbound.

## Definition of done — every check, in order, before calling a package done (full mechanics: references/quality-gates.md)
0. SMOKE-TEST UPSTREAM first, outside YunoHost (scratch port, throwaway creds); exercise login + core API; delete scratch state after.
1. INSTALL as a background job (`yunohost app install <dir> -a "k=v&k=v" --force`; `unset PYTHONPATH`; args match manifest keys exactly, `&`-joined). Autopsy failures with `--no-remove-on-failure`.
2. FUNCTIONALITY GATE: real browser, real portal login, primary write path exercised end-to-end + renders on reload; watch ~15 s for login bounce loops; prove nginx serves built output. If the app sends mail, ALSO the mail-send gate (rule 11). Mechanics: references/quality-gates.md §0a-0b.
2b. ENDPOINT MATRIX (quality-gates.md §0c): from ssowat conf.json — every public permission URI anonymously NEVER 302s, every protected one DOES. Catches regex URIs and permission-wiring bugs all other gates miss.
3. CONFIG PANEL round-trip: get → set (`-a "k=v&k=v"` with SHORT setting names) → get, gated on the RENDERED FILE's content (CLI exit lies); settings-bound panels need a `ynh_app_config_apply` override that re-renders files. What to expose + wording doctrine: references/ui-questions-panels-docs.md.
4. BACKUP → REMOVE → RESTORE, then RE-RUN the functionality gate on the restored app. Canary (DB row + panel change) created RIGHT BEFORE the backup, asserted after. After any repo fix: upgrade first (refreshes the archived scripts), THEN re-create the backup, THEN test restore.
5. UPGRADE ×2: same-version `app upgrade -u <clone> -F` twice, then re-run the functionality gate — the second pass catches fresh-install-only scripts.
5b. CHANGE_URL MOVE (quality-gates.md §5 CHANGE_URL MOVE): relocate the live install once (new path, or second domain for full-domain apps — `yunohost domain add` one if the box has none; app that fundamentally can't move → document + exclude `change_url` in tests.toml + prove the backup→remove→reinstall→restore fallback), re-run 2b + functionality gate + canary read, move back. An unexecuted change_url is an untested script.
5c. REINSTALL (quality-gates.md §5 REINSTALL GATE): plain `remove` (data dir retained) → fresh install → functionality gate + data-dir canary — the local twin of CI's install/remove/reinstall scenario; for multi_instance=false apps the only second-install proof (CI skips install.multi when false).
5d. MULTI_INSTANCE DECLARED RIGHT (quality-gates.md §Multi-instance decision rule): true by default; false only for machine-global resources, reason stated in a manifest comment + ADMIN.md; false packages SELF-GUARD install (YNH 12.1 does not refuse a second copy — official-docs.md §15.6).
6. REMOVE cleanly: no stale services/sudoers/nginx maps; half-registered apps need the placeholder-unit trick (references/traps-lifecycle.md).
7. LINTER clean except 'not in catalog', output PASTED into the REPORT (evidence, not assertion). Known shapes: `cpe = "???"` placeholder fails the manifest schema — set a real `cpe:2.3:a:<vendor>:<product>`; 'could not be parsed' lines on multi-line `bash -c` strings are parser noise — live gates arbitrate.
8. ASSETS + tests.toml: rule-10 set complete; test_upgrade_from entries from the repo's OWN history; `args.<key> = "ci-..."` for required-no-default install questions; every pinned source declares `autoupdate.strategy` (+ per-arch `asset` regex, stable-tag-constrained per repo-hygiene's prerelease trap) — 77% of the top-star catalog ships it (2026-10 audit), it is inert-but-ready in personal repos, and dry-testable with autoupdate_app_sources.py (official-docs.md §autoupdate).
9. PRIVACY SWEEP (rule 9) before every push.
10. REPORT: what passed; what's gated on user approval (pushes); what does NOT survive reinstall documented in doc/ADMIN.md.

## Upgrade-durability (what sticks) — 3-line summary
- setup_source re-extracts on EVERY pass; config_add always overwrites; panel applies re-render from the ARCHIVED tree — repo fixes land only after `app upgrade -u <clone>`. settings.yml survives upgrades, wiped on remove.
- Fix routing: small app-code fix → `patches/<source_id>/` (with the durability copy into /etc/yunohost/apps/$app/, see traps-lifecycle); big divergence → fork + pin in [resources.sources]; config → conf/ template; runtime files → one shared _common.sh deploy function on install+upgrade+restore.
- `--keep` is the only sanctioned mutable set inside $install_dir; app-written data belongs in $data_dir. Full doctrine + restore/patch mechanics: references/traps-lifecycle.md.

## Skill repo maintenance
This skill directory is itself a git repo (branch `main`), PUBLISHED at https://github.com/quartztester/ynh-app-packaging-skill (GPLv3; other agents install from its raw SKILL.md URL). Rules:
- After ANY edit to SKILL.md, references/, scripts/ or templates/ — COMMIT it: author `$COMMIT_AUTHOR`, message naming the change; tag `v<version>` on version bumps; a change to scripts/ lands only after the modified check is proven on crafted fixtures that must pass AND must fail — a check that cannot fail is a false green. An uncommitted edit is lost history. Git history begins at v2.8.0; earlier versions were never tracked.
- START every session in the skill repo with `git status` — a prior session can leave uncommitted edits. Review and land foreign changes as their OWN commit before yours; when both changesets touch one file, split with exact-string anchors: snapshot the final file, rebuild the intermediate state by replacing your new wording back to the old (assert each anchor occurs exactly once), commit the foreign set, reverse-replace, `diff -q` against the snapshot to prove the tree byte-identical, then commit yours.
- PUSH, then VERIFY the push: push with the wired credential helper (never the PAT in a remote URL), then confirm remote HEAD sha == local HEAD — querying the ref you actually pushed, branch derived via `git branch --show-current` (a read-back on a hardcoded wrong branch silently matches nothing) — the expected tags exist on the remote, and the raw SKILL.md URL fetches anonymously with the current frontmatter. A push that was not verified is not published.
- PUBLIC-RELEASE BAR, kept met on every push: LICENSE is the canonical GPLv3 text fetched from gnu.org — never hand-write legal text; README.md stays dual-audience (what/why, what you get, install URL, AI-transparency quote); personal environment values appear ONLY as the conventions-block defaults — new rules use the `$GH_ACCOUNT`/`$GH_TOKEN_FILE`/`$WORKSPACE`/`$COMMIT_AUTHOR` variables, never the maintainer's literal account or paths.
- Research-driven content changes (doc audits, upstream orgs, issues) are RECOMMENDED to the user first and implemented only after approval — never rewrite the skill unilaterally from a research pass.
- Commits to THIS repo are AI-assisted work and end with the `Assisted-by: <agent>:<model>` trailer that CONTRIBUTION.md mandates — the repo eats its own dog food. Human-facing docs (CONTRIBUTION*.md, philosophy.md) cite every factual claim to a source verified in the same session (the user prefers citation-heavy prose); block quotes are re-fetched verbatim from the source, never retyped from memory, and follow the fr-pairing doctrine where the doc set has one.
- EFFORT PRIORITY (user rule): the skill exists to make PACKAGING correct; benchmarking is secondary attribution. Every live-gate failure on a with-skill package is a skill gap — fold it into a trap or gate rule before anything else. Run a baseline arm only when a NEW gate class needs attribution, not every cycle.
- ANTI-STUFFING (user rule): one canonical home per trap family — other references point to it, never restate it. A new trap/gate enters only after a live gate failure proves it, or when it covers a script every package ships untested (e.g. change_url). verify_skill_integrity.py's per-reference line budget enforces this at commit time — run it as the gate before EVERY commit, not only after adding a file (a prior session can leave a reference over budget); a SIZE failure means split or compress the file, never raise the budget — the fact-preserving compression unwraps hard-wrapped multi-line bullets into the file's single-line bullet style, checked content-identical by whitespace-insensitive comparison.
- Everything rule 9 demands of app repos applies to THIS repo too: no personal identifiers, private domains, IPs, or box-specific paths in any file or commit — it is public-bound.
